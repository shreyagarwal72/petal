# Petal ad-block / privacy upgrade - findings and master prompt (from the 0c4afb78 zip)
Static analysis only; nothing compiled or run. GeckoView API names below must be checked against the 159 Javadoc before use.

## Findings (why the built-in blocker is weaker than it looks)
1. NO SUBRESOURCE NETWORK BLOCKING BY PETAL RULES. PetalAdBlockEngine.shouldBlockUrl() is called only from BrowserActivity.adoptPreparedWindow (popup windows) and AdBlock.isAd/BannerBlock helpers. GeckoView has no subresource interception hook (onLoadRequest/onSubframeLoadRequest see navigations and frames only). The ~1.6k-line rule set (EasyList, uAssets, Hagezi, procedural rules) therefore never stops an ad script, image or XHR from being fetched. Real blocking comes only from Gecko's own ETP lists.
2. COSMETIC/SCRIPTLET INJECTION IS LATE AND FRAGILE. injectPagePrivacyAndAdBlock() runs on page stop and does gs.loadUri(<javascript: payload>). That is after ads loaded, is blocked by CSP on many sites, and goes through the navigation path (can disturb history/loading state). It cannot run at document_start.
3. NATIVE ENGINE ABSENT. libadblock_petal.so is not in the tree; BraveAdblockJni logs "not available" and the Kotlin trie fallback runs.
4. ETP FLAGS ARE THIN. PetalGeckoRuntime sets EtpLevel STRICT + cookieBehavior ACCEPT_FIRST_PARTY_AND_ISOLATE_OTHERS (Total Cookie Protection) + AntiTracking DEFAULT|AD|STP + SafeBrowsing DEFAULT. Fingerprinting and cryptomining flags, cookie purging, bounce-tracking and query-parameter stripping are not set (verify availability in GeckoView 159 ContentBlocking.Settings).
5. Built-in WebExtensions (scriptlet_defuser, consent_manager, clean_link, ...) do not include a network blocker; none declares webRequest/declarativeNetRequest for ads.

## What Firefox and forks do (references)
- Firefox for Android ETP: Standard = social trackers, cross-site trackers, cryptominers; Strict adds tracking content and Total Cookie Protection; Custom picks cookies/tracking content/cryptominers/fingerprinters (Mozilla support article, 2021 revision - older, re-check).
- Brave adblock-rust (github.com/brave/adblock-rust): network blocking, cosmetic filtering, scriptlet injection, resource replacements, ABP/uBO/hosts syntax, rule attribution; Rust + JS bindings. Brave runs it inside the browser network layer, which Petal cannot do under GeckoView.
- Firefox-based forks (e.g. Mull, Fennec/IronFox-style builds) ship or recommend uBlock Origin as a WebExtension; uBlock Origin runs on Firefox Android through GeckoView's WebExtension APIs, which shows webRequest blocking works there. (From general knowledge - not verified in this audit.)

## Recommended architecture
Network layer = a bundled WebExtension (best: official uBlock Origin XPI with its filter lists; alternative: a Petal-owned MV2 extension using webRequest blocking or declarativeNetRequest fed by Petal's compiled rules). Keep Gecko ETP Strict + TCP as the base layer. Replace javascript: injection with extension content scripts at document_start (cosmetic + scriptlets). Keep PetalAdBlockEngine only for popups, stats and settings; use adblock-rust only inside the extension (WASM/JS binding) or drop the JNI layer.

## Master prompt (paste into Claude Code at repo root; compiler + device required)
Read docs/ADBLOCK_UPGRADE_PLAN.md. Goal: real, private, effective blocking on GeckoView without breaking sites or extensions. Do all stages in one session; build + test after each; commit per stage.
Stage 1 - Measure: add a debug "blocking report" that loads a fixed set of ad/tracker test pages (e.g. EasyList/uBO test pages, a news site, a video site) and records requests that reached the network, requests blocked by ETP, cosmetic elements hidden, page load time and memory. Capture the baseline before changing anything.
Stage 2 - ETP hardening: verify against the GeckoView 159 ContentBlocking.Settings Javadoc, then enable Strict, fingerprinting and cryptomining protection, cookie purging, bounce-tracking protection, query-parameter stripping and email-tracker blocking where available; keep Total Cookie Protection; expose a Standard/Strict/Custom choice that maps to Mozilla's definitions; per-site exceptions via the existing whitelist; private tabs always Strict.
Stage 3 - Network blocker extension: bundle uBlock Origin (official signed XPI, keep GPLv3 notices and its list updater) OR build petal_network_blocker (MV2, webRequestBlocking or DNR) compiled from the existing assets (easylist, uassets, hagezi, petal_default_rules, allowed host pairs, advanced/procedural rules, consent rules). Install via the existing PetalBuiltInExtensionManager through the engine so it works in normal and private tabs (set allowedInPrivateBrowsing deliberately). Support: per-site toggle wired to the Petal shield sheet, blocked-count badge fed back to PetalAdBlockEngine stats, filter list subscriptions and custom rules from PetalFilterSubscriptionManager, first-party/same-party allow pairs to avoid breakage.
Stage 4 - Cosmetic + scriptlets: move to extension content scripts at document_start (scriptlets in MAIN world where supported, cosmetic CSS with early insertion, procedural filters); delete the gs.loadUri(javascript:) injection path; keep anti-adblock-defuser; verify CSP-strict sites and SPA navigations.
Stage 5 - Engine cleanup: if the extension owns blocking, remove BraveAdblockJni / PetalBraveShieldEngine / the Kotlin trie request path, or keep adblock-rust only inside the extension; fix or remove libadblock_petal packaging; keep PetalAdBlockEngine for popup blocking, stats and settings. One source of truth for rules (no duplicate parsers).
Stage 6 - Privacy extras: WebRTC leak protection, referrer trimming, GPC and DNT headers, third-party storage partitioning check, HTTPS-only mode, tracking-param stripping for shared links (petal_clean_link), DoH already present - verify they work together and in private tabs; make sure no filter-list update request carries cookies or identifiers.
Stage 7 - Verify: rerun the Stage 1 report and compare (requests reaching network must drop sharply, no regression in load time > 10%, memory increase documented); test breakage on login, payments, video, maps, captchas, news paywalls; extension install/popup still works; per-site toggle; private tab behaviour; filter update and offline start; battery/CPU in a 10 min browsing run. Report what improved, what broke, what is unverified.

## Status (applied directly, uncompiled)
- Ad-block is now a single on/off switch: PetalAdBlockMode has only DISABLED/STANDARD (legacy "aggressive"/"strict" values fold into ON); the 3 mode cards, the per-site Standard/Aggressive chips (shield sheet + site info sheet) and the crude "aggressive heuristics" in PetalAdBlockEngine.shouldBlockUrl are removed.
- ON now applies TrackingProtectionPolicy.strict() per session (it was recommended(), which overrode the runtime EtpLevel.STRICT).
- Gecko AntiTracking flags add CRYPTOMINING and FINGERPRINTING when blocking/strict is on (verify constants against GeckoView 159).
- Misleading copy removed ("High-Performance Trie", "uBlock Origin/AdGuard-grade", "Brave modes").
- NOT done: network-blocking extension, document_start cosmetics/scriptlets, native lib packaging, page-wide row cleanup, benchmark vs Brave - see docs/MASTER_PRIVACY_ADBLOCK.md stages 1,2(rest),4-8.
